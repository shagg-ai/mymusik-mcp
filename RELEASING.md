# Publish MyMusik MCP 0.2.0

Run these steps from the standalone release repository with publishing access to shagg-ai/mymusik-mcp. Publishing the Python package to PyPI also requires a PyPI publisher account. The connector and plugin code use the MIT license.

1. **Prepare the repository.** Publish this folder as `shagg-ai/mymusik-mcp` on GitHub. Include the hidden marketplace and plugin manifests. The Python package and Claude plugin use the bridge in `plugins/mymusik/mymusik_mcp`. Codex runs the wheel built from that directory. When preparing later versions from demo_cmake, refresh `mcp_stdio.py` there from `deps/Framework/Library/RestApiServer/tools/mcp_stdio.py` and rerun its connector tests.
2. **Verify the Python artifacts.** Reuse the verified wheel and source archive in `dist`. To rebuild in a clean checkout, run `python -m pip install build twine`, then `python -m build` and `python -m twine check --strict dist/*.whl dist/*.tar.gz`. Install the wheel in a fresh environment and complete the pairing walkthrough before publishing. Keep the package version, plugin versions and registry package version aligned.
3. **Release the artifacts on GitHub.** Run `python build_mcpb.py` and record its SHA-256 in the MCPB package entry in `server.json`. Its identifier must point to the matching release asset. Create the version tag and GitHub release, then attach the wheel, source archive and MCPB using `gh release upload v0.2.0 dist/mymusik_mcp-0.2.0-py3-none-any.whl dist/mymusik_mcp-0.2.0.tar.gz dist/mymusik-mcp.mcpb`. For PyPI distribution, run `python -m twine upload dist/mymusik_mcp-0.2.0-py3-none-any.whl dist/mymusik_mcp-0.2.0.tar.gz` as an authorized PyPI publisher and verify installation in a clean environment.
4. **Publish the official MCP Registry entry.** With the updated listing and workflow on the default branch, run `gh workflow run publish-registry.yml --repo shagg-ai/mymusik-mcp`. The workflow downloads the public bundle, verifies its hash, authenticates via GitHub OIDC and publishes the local stdio listing. Check that the registry returns the expected version, asset URL, SHA-256 and active status. [Public registry record](https://registry.modelcontextprotocol.io/v0.1/servers/io.github.shagg-ai%2Fmymusik-mcp/versions/latest)
5. **Submit to Claude.** Run `claude plugin validate ./plugins/mymusik`. In the developer portal, select **Submit new → Plugin bundle**, choose `shagg-ai/mymusik-mcp`, enter `plugins/mymusik` as the plugin path, and select `v0.2.0`. Validate, complete the data handling questions using the plugin README, and submit for review. [Claude developer portal](https://claude.ai/directory/manage)
6. **Distribute to Codex.** Once the GitHub repo is available and the wheel is installed on PATH, users run `codex plugin marketplace add shagg-ai/mymusik-mcp` followed by `codex plugin add mymusik@mymusik-plugins`. Pair and open a fresh local session. OpenAI's official desktop directory has a separate approved-partner process. [OpenAI desktop submission guide](https://developers.openai.com/plugins/deploy/desktop-only)
7. **Distribute to Gemini CLI.** Run `python build_gemini.py` and attach `dist/win32.mymusik.zip`, `dist/darwin.mymusik.zip` and `dist/linux.mymusik.zip` to the same release. These archives contain the root extension manifest and bundled connector. Test the GitHub install command without a branch override in an isolated Gemini CLI home.

## Windows desktop installer

On Windows x64, install Python with Tk, PyInstaller 6 and NSIS 3. From the connector root run `python build_windows.py --makensis "C:\Program Files (x86)\NSIS\makensis.exe"`. The outputs are `dist/MyMusik-MCP-Setup-x64.exe` and `dist/MyMusik-Windows-x64.mcpb`. The installer includes a copy of the Windows extension for offline installation. Test installation, the Start menu shortcut, the copied JSON launch command, and uninstallation under a standard Windows account before distributing the installer. Direct pairing settings also require the matching desktop player update.
